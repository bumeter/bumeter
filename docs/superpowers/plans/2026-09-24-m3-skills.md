# M3: Skills — Implementation plan (condensed)

- Spec: `docs/superpowers/specs/2026-09-24-thongke-design.md` (sections 6, 8, 11, 14)
- Wireframe: screens 3 (Skill) and 4 (install / confirm dialog) in `2026-09-24-thongke-wireframes.md`. Style per section 6.0.
- Goal: a Skill screen that lists every skill, compares baseline cost with real usage, with a "where used" list and suggestions. It supports disable/enable/install/remove in 2 steps plan → apply, with undo.
- Branch: `feat/m3-skills` (branched off `feat/m2-dashboard`). Follow TDD, one commit per task.

## Real data on the machine (already checked)

- Personal skills: `~/.claude/skills/<name>/SKILL.md` with frontmatter `name` and `description`. There are symlinks, e.g. `pj-clarify` → `~/skills-repo/pj-clarify`.
- `~/.claude/skills/synced/<uuid>/…`: skills synced from claude.ai. The app is **read-only** for them, never disables or removes.
- Plugins: `claude plugin list --json` returns `[{id, version, enabled, installPath, …}]`. `claude plugin details <name>` returns a text table `component  always-on  on-invoke` (e.g. `~70  ~6.3k`).
- When used, a skill inside a plugin is named `<plugin>:<skill>` (e.g. `superpowers:brainstorming`). A slash command is named `/…`.

## General rules

- Only operate plugins through the `claude plugin` CLI, never edit the plugin config files directly.
- Every operation goes through `plan` (showing exactly which files are affected) → `apply` → write the `skill_ops` journal → optionally `undo`.
- Disabling a skill = move it to `~/.claude/skills-disabled/`. Removing a skill = move it to `data_dir/trash/<ts>-<name>`, kept for 30 days. For a symlink, only move or delete the link, **never touch the source directory**.
- The baseline cost of a personal skill is an estimate: the character count of `description` ÷ 3.5. The cost per call: `SKILL.md` length ÷ 3.5. The UI states "estimate" clearly.
- Tests use a temporary HOME and a fake `claude` CLI placed at the front of `PATH`. Never run on the real `~/.claude`.

## Review Focus

1. A skill is a symlink pointing to the user's repo → disable/remove/undo **never** deletes or moves the source directory (Task 4).
2. Remove then undo, or undo twice → no data loss, no ambiguous errors (Task 4).
3. The `claude` CLI is missing, slow, or changes output format → the Skill screen still shows personal skills (Tasks 2, 5).
4. A skill name or description containing odd characters or `<script>` → shown as text (Task 6).
5. A Claude session is running and a skill is disabled → the UI notes "takes effect from the next session" (Task 6).
