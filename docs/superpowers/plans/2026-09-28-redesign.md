# Bumeter — UI redesign + rename: Implementation plan (condensed)

> Executor: use superpowers:subagent-driven-development (or executing-plans); one commit per task, follow TDD.

- **Goal:** redo the UI layer per the standard Bumeter mockup (orange, friendly, Bum mascot, flat buttons, width-responsive layout) and rename thongke → Bumeter (CLI `bum`, new data directory, automatic data migration).
- **Architecture:** tokens + shared components in `app/ui/src/components/`; `main.ts` sets `#app[data-layout]`; views keep their data-fetching, only the display changes. Rust: `Config.theme`, tray expression selection, data-directory migration, binary rename.
- **Stack:** plain TypeScript + `h()`, Vite, Vitest + happy-dom; Rust (tk-core, app/src-tauri, tk-cli); Tauri 2.
- **Spec:** `docs/superpowers/specs/2026-09-28-redesign-design.md`. **Standard mockup:** `docs/superpowers/specs/2026-09-28-redesign-mockups/bumeter-ui-mascot.html`. Brand: `docs/brand/README.md`, SVG `docs/brand/bum/bum-{happy,calm,worry,blaze,sleep}.svg`.
- **Branch:** `feat/bumeter` (from `public-main`, connected to GitHub `origin/main`).
- **Skills to use:** `frontend-design` (tokens, components, each screen), `dataviz` (charts, bars), `web-design-guidelines` (review in Task 12).

## General constraints

- Colors, fonts, corner radii, buttons: exactly as in tables 2 and 3.1 of the spec (`#FF7A1A`, `#E8640A`, `#FFF0E3`, `#FF4B2B`, `#22A05A`; light background `#FAF7F4`/`#FFFFFF`, dark `#15120F`/`#1F1A16`; `--r-panel 16px`, `--r-box 12px`, `--r-ctl 10px`, `--r-tag 5px`).
- **No gradients anywhere.** No shadows for buttons/chips/frames; shadows only for the drawer, dialogs, and menus.
- Font **Be Vietnam Pro** embedded offline (`@fontsource/be-vietnam-pro`), replacing Inter.
- Width breakpoints: `wide` ≥ 1200px, `medium` 700–1199px, `narrow` < 700px.
- All displayed text goes through `t()` (vi + en) and `textContent`; no `innerHTML` with data. Bum's SVG is a constant in code, not taken from data.
- Do not add a UI framework. On `prefers-reduced-motion`, disable the drawer animation.
- Internal crate names `tk-*` stay as they are; only change what the user sees.

## Review Focus

1. **Changing width while the drawer is open** (medium → wide): the drawer closes, the detail shows in the right column, and the detail is not mounted twice. Tested in Task 5.
2. **Esc while typing in the search box with the drawer open:** Esc closes the drawer, the search text is kept. Tested in Task 5.
3. **`data-changed` arrives while the drawer is open:** the content updates, the drawer stays open, the open turn is kept. Tested in Task 5.
4. **Save immediately with a value mid-typing** (typing "7" in "70"): the debounce doesn't save an invalid value; leaving the field reports the error. Tested in Task 8.
5. **The machine already has thongke data and is running the old app** (old socket/lock still present): the new app migrates the directory without breaking the open DB; if it can't migrate, it uses the old directory and still runs. Tested in Task 11 (`KeptLegacy`).
